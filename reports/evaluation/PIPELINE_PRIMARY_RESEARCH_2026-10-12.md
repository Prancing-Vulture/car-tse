# Primary research for the wake-to-intent pipeline

**Research date:** 12 October 2026  
**Purpose:** Map primary literature, source repositories, and dataset evidence to the next tests and code changes in this repository. This is a research note, not evidence that proposed changes improve this pipeline.

## Findings that matter for this repository

The current continuous proxy cannot establish same-driver performance: the audit says the wake and command speakers are not checked for identity. That is a consequential design issue for this particular stack because SpEx is explicitly conditioned on an enrolled speaker. In the current pipeline, Stage 4 immediately takes `argmax` over its intent logits and maps that label to an action; it has no confidence-based defer decision. Its post-wake input is a fixed-length crop, while command audio is gated by Stage 2 and can end after a configured speech-silence condition or a timeout. These behaviors make the exact samples received by Stage 4, and what words those samples contain, the key evidence to collect before changing models.

The literature points toward a narrow first pass:

1. **Instrument audio end to end before changing model weights.** Record one continuous session per trial where the same enrolled person says the actual wake word and then a labeled command. Save the source, SpEx output, every Stage 2 score and decision, every appended source-time segment, the exact Stage 4 tensor, logits, and action. For each trial compare the known command crop, the raw-mixture crop, the oracle-timed crop of the frozen SpEx output, and the actual Stage 4 input. These paired comparisons localize where information disappears; because the measurements share one trial and one processing chain, they are diagnostic evidence and not independent estimates of each stage’s performance.
2. **Keep SpEx and its default checkpoint fixed for that diagnosis.** SpEx+ expects a reference from the target speaker, and papers on extraction show performance depends on the auxiliary reference and input condition. The current v10 source-time overlap does not demonstrate that the target words survived separation. Change extraction only if the paired audio comparison shows a repeatable loss or material distortion.
3. **If Stage 2 or 3 is implicated, optimize their joint continuous operating point with disjoint partitions.** Mine hard-negative examples only from training sessions and train on those examples. Use separate development sessions to select the score threshold, temporal confirmation, and cooldown behavior based on full-session misses, false actions, and latency. Keep final held-out speakers/sessions locked from mining, training, calibration, and threshold selection. The existing ratio study and clip metrics do not support another sampler-ratio sweep.
4. **Only after received audio is verified, evaluate Stage 4 on correctly aligned separated commands.** Report intent accuracy and a risk-versus-coverage curve, the standard way selective prediction describes the accuracy/coverage trade-off [Geifman and El-Yaniv, NeurIPS 2017](https://papers.neurips.cc/paper_files/paper/2017/file/4a8423d5e91fda00bb7e46540e2b0cf1-Paper.pdf). If actions need to be withheld for uncertain commands, calibrate a confidence score on development audio from the same post-SpEx distribution and define an explicit “repeat/confirm” result. A raw maximum softmax score should not be treated as a calibrated probability, particularly under cabin/noise shift. The cited selective-classification work is general classification research, not a result on audio or this intent model.
5. **Accept on locked continuous sessions, not component scores.** Hold out drivers and recording sessions (and vehicles when available). Include long target-absent spans. Count user-visible false actions per target-absent hour under a frozen event-grouping policy; report the exposure and uncertainty. Under a homogeneous Poisson approximation, zero events in `T` hours has a one-sided 95% upper rate bound of `-ln(0.05)/T`, approximately `2.996/T` events/hour. State the assumption and also show results by session/condition; clustered events or varying environments make a single constant-rate model questionable. Bootstrap positive success and latency by complete drivers/sessions rather than overlapping windows. Latency should run from the wake/command event through endpointing and model/action completion, so context lookahead and endpoint delay are included.

No paper result below guarantees a gain on this code, wake word, cabin acoustics, or action set. Published metrics motivate a measurement or method; the repo’s locked full-pipeline results decide whether it helps.

## Evidence mapped to code and decisive tests

| Evidence | Why it applies | Repository change to consider | Decisive test |
|---|---|---|---|
| **Speaker-conditioned extraction is conditional on correct target identity.** SpEx/SpEx+ extract a target using speaker reference information. Work that varies auxiliary information finds that it does not invariably improve extraction and tests distorted/mismatched reference cases. | The proxy uses separate corpora and does not verify wake-speaker = command-speaker = enrolled-speaker. A valid evaluation must meet the conditioning assumption before it can judge extraction. | No SpEx edit in the first remediation pass. Add matched identity and waveform provenance to the diagnostic recorder/evaluator; carry reference, target, and command speaker IDs in trial metadata. | Same speaker performs enrollment, wake, and command. Listen/inspect aligned source, frozen SpEx output, and Stage 4 crop, then measure command intelligibility and paired downstream prediction. Include a passenger command as a negative control. |
| **Streaming KWS has a latency/accuracy trade-off.** Rybakov et al. compare streaming and non-streaming inference on-device and report accuracy/latency trade-offs. | Current Stage 3 scores come from clips and a few short proxy scenes; a threshold alone cannot choose the desired operating point. | Keep current detector while adding per-event decision support and full-session timing; later tune threshold, confirmation, and refractory behavior jointly on continuous dev data. | Held-out continuous target-present trials plus long target-absent media/passenger/noise audio. Plot miss and false-event rates against wake-to-action latency at candidate operating points. |
| **Difficult negative regions can matter more than arbitrary class ratios.** Hou et al.’s Regional Hard-Example method selects multiple high-scoring non-keyword regions with spacing, dynamically, to address imbalance while preserving negative diversity. Their paper reports gains at a fixed FAR on their own wake words and datasets. | This aligns with the repository’s high false-accept trade-off, while the local three-seed ratio study found essentially tied validation F1. | If Stage 3 is confirmed as a cause, mine and train on hard negatives from labeled **training-only sessions** after frozen SpEx. Use a separate development partition only to choose the sampler/settings and thresholds; never train or mine from development or locked test sessions. Preserve speaker/session separation and avoid selecting only one repeated confuser. Keep the current sampler ratio as the baseline. | Compare the trained candidate with the frozen checkpoint using separate development sessions for decisions; then do one locked held-out full-pipeline run. Do not carry the paper’s relative gains over as a forecast. |
| **Endpointing trades early cutoff against delay.** Raju et al. describe premature truncation from pauses, hesitation, overlap, and background noise; their two-pass endpoint arbitrator tests early-cutoff and latency jointly. | The runtime has a post-wake command capture state, fixed-length Stage 4 crop, presence gating, silence-based completion, and timeout. The audit has not proven these caused v10 failures. | Instrument the current capture path first. If matched recordings show truncation, retain a timestamped ring buffer and use a development-tuned endpoint policy with an explicit maximum wait; preserve audio through the chosen endpoint. | Replay commands with short/long post-wake pauses, within-command pauses, differing lengths, and competing passenger speech. Score complete command retention and end-to-end latency against labels. |
| **Intent confidence can be miscalibrated; selective systems trade risk for coverage.** Gong et al. directly study calibration for intent detection. Geifman and El-Yaniv formalize general deep-network rejection in terms of bounded risk and coverage; their experiments are on image data, so this only supplies evaluation framing here. | Runtime currently always emits the `argmax` intent/action, including on out-of-domain or damaged audio. Clean Fluent Speech Commands accuracy does not estimate confidence on post-SpEx cabin audio. | After Stage 4 input is validated, collect correctly aligned post-SpEx command examples on development speakers; calibrate/validate confidence there and add an explicit defer/confirmation output. Do not interpret `max(softmax)` as confidence until tested. | Report calibration error plus risk-coverage curve on held-out speakers/sessions. At chosen coverage, count wrong actions and abstentions; test noise, passenger speech, silence, and malformed/truncated input separately. |
| **Wake false accepts require substantial representative negative exposure.** The openWakeWord evaluation guidance calls for realistic positives and hours of target-absent continuous speech/noise, and documents roughly 5.5 h of its negative corpus. | The local eight scenes last seconds and cannot support an hourly estimate. | Add long target-absent recordings and declare what groups consecutive model hits into one false event before threshold selection. Compute rate using target-absent time only. | Report event count, negative exposure hours, rate, exact one-sided Poisson bound, and per-session/condition distribution. If zero events, report the bound rather than claiming zero risk. |
| **Speaker-disjoint partitions are part of the evaluation design.** Fluent Speech Commands provides speaker IDs and its published split has no speaker in more than one split; Hey Snips research data reports separate speakers by split. | Window-level random splits or reused speakers would overstate transfer to new drivers. | Maintain speaker/session/vehicle split identifiers in manifests and result metadata; unit of resampling for positive success should be whole speaker/session. | Freeze a test manifest with no driver/session overlap with training or threshold-selection data and publish counts by independent unit. |

## Dataset search and compatibility

I checked public sources for a ready-made same-speaker wake-plus-command dataset that fits this project’s “Marvin” KWS and 31-intent head. None of the candidates verified all of those requirements. The current continuous proxy remains diagnostic only.

| Dataset/source | Verified contents and access | Fit to this task |
|---|---|---|
| [Fluent Speech Commands](https://fluent.ai/fluent-speech-commands-a-dataset-for-spoken-language-understanding-research/) | 30,043 single-utterance recordings, 97 speakers, speaker IDs and 31 intents; split by speaker. Academic research only, CC BY-NC-ND 4.0. The dataset page provides a download route. | Best match for intent labels, but no wake word or continuous wake-to-command sessions. It cannot establish a same-speaker wake-to-command pipeline score. The local audit already flags the need to use official manifests rather than training-derived slices. |
| [Sonos/Hey Snips research dataset repository](https://github.com/sonos/keyword-spotting-research-datasets) | “Hey Snips” wake examples and same-domain negatives with speaker IDs; dataset access is via request form, research-only/noncommercial terms. The repository says wake clips contain the wake phrase and the negative examples share recording conditions. | Useful precedent for KWS evaluation and same-domain negatives, but does not provide the project’s Marvin phrase or FSC command labels, and it is not a wake-plus-command dialogue set. No download is recommended for the immediate paired diagnostic. |
| [University of Rochester Smart Speaker Command Dataset](https://rochester.figshare.com/articles/dataset/Smart_Speaker_Command_Dataset/26417548) | Landing page says each 448.68 MB archive item is a voice command beginning “Hey Alexa”; license CC BY 4.0; it asks users to fill out a registration form. A companion manual repeats these facts. | Closest public wake-plus-command recording lead, but trigger is Alexa, not Marvin. The landing page/manual does not establish that its speaker metadata, transcript/intent schema, enrollment audio, or continuous session format can be mapped to this repo. It is not a valid locked acceptance set for this pipeline. Do not download before verifying the archive schema and a concrete use. |
| [Google Speech Commands paper](https://arxiv.org/abs/1804.03209) and [official data](https://storage.googleapis.com/download.tensorflow.org/data/speech_commands_v0.02.tar.gz) | Short isolated words; standard KWS training/evaluation dataset with per-speaker filename IDs and defined split lists. | Can provide Marvin wake examples as the current system already uses it; it cannot pair a wake recording with an FSC command speaker. |

The evidence supports collecting a small, consented, explicitly labeled same-driver continuous diagnostic set as the next discriminating test. Public wake and intent corpora may help create development examples only when speaker identity is actually verifiable. Joining separate public datasets by row order, demographic resemblance, or an unvalidated voice match would recreate the mismatch under investigation. A stitched pair can test software mechanics but should be labeled as synthetic diagnostic audio, never as natural continuous-driver performance.

## Verified primary sources and repositories

1. **Journal article — SpEx:** Xu, Rao, Chng, and Li, [“SpEx: Multi-Scale Time Domain Speaker Extraction Network,” IEEE/ACM Transactions on Audio, Speech, and Language Processing 28 (2020)](https://doi.org/10.1109/TASLP.2020.2987429). Describes a speaker encoder, extractor, and reference-conditioned target output; its reported open-evaluation improvements are specific to the paper’s benchmark. The authors’ [official SpEx code repository](https://github.com/xuchenglin28/speaker_extraction_SpEx) also documents that the original TensorFlow paper result and the later PyTorch reimplementation are not identical implementations.
2. **Conference paper — SpEx+:** Ge et al., [“SpEx+: A Complete Time Domain Speaker Extraction Network,” Interspeech 2020](https://www.isca-archive.org/interspeech_2020/ge20_interspeech.html). The paper frames extraction around a target-speaker reference and reports WSJ0-2mix-extr results. The authors’ [SpEx+ (tied) source repository](https://github.com/gemengtju/SpEx_Plus) contains training and decode scripts. These sources motivate keeping enrollment identity matched; they do not establish cabin-command intelligibility for this checkpoint.
3. **Journal article — auxiliary information limits:** Elminshawi et al., [“New Insights on Target Speaker Extraction,” arXiv primary paper](https://arxiv.org/abs/2202.00733), subsequently published in [Frontiers in Signal Processing (2024)](https://doi.org/10.3389/frsip.2024.1440401). Across tested systems/data, auxiliary information did not always beat uninformed separation; the paper investigates changed and distorted auxiliary inputs. This supports measuring the actual enrolled/reference condition rather than assuming extraction quality from architecture name alone.
4. **Conference paper and official code — streaming KWS:** Rybakov et al., [“Streaming Keyword Spotting on Mobile Devices,” Interspeech 2020](https://doi.org/10.21437/Interspeech.2020-1003), and Google Research’s [kws_streaming repository](https://github.com/google-research/google-research/tree/master/kws_streaming). The work evaluates streaming/non-streaming accuracy and latency trade-offs. Its code demonstrates streaming state implementation; neither its phone results nor its model are performance guarantees for this project.
5. **Conference paper and author code — hard-negative mining:** Hou et al., [“Mining Effective Negative Training Samples for Keyword Spotting,” ICASSP 2020](https://doi.org/10.1109/ICASSP40776.2020.9053009), [author-hosted paper](https://www.microsoft.com/en-us/research/uploads/prod/2020/04/ICASSP2020_Max_pooling_KWS.pdf), and the authors’ [PyTorch repository](https://github.com/jingyonghou/KWS_Max-pooling_RHE). Regional Hard-Example mining picks difficult negative regions while suppressing nearby redundant frames. The paper’s FAR-specific improvements are on its own systems and wake tasks. The code documents a legacy Python 2.7/PyTorch 1.4/Kaldi environment, so it is a method reference, not a drop-in dependency or independent replication.
6. **Primary paper preprint — endpointing:** Raju et al., [“Two-pass Endpoint Detection for Speech Recognition,” arXiv 2024](https://arxiv.org/abs/2401.08916). The authors explicitly analyze early cutoffs against latency and discuss noise, overlap, hesitations, and within-utterance pauses. It motivates a labeled pause/endpoint test, not an immediate substitution of this project’s capture logic.
7. **Conference paper — intent calibration:** Gong et al., [“Confidence Calibration for Intent Detection via Hyperspherical Space and Rebalanced Accuracy-Uncertainty Loss,” AAAI 2022](https://doi.org/10.1609/aaai.v36i10.21314). Reports overconfidence concerns and calibration experiments for intent detection on public datasets. It supports measuring probability quality; its specific training method should not be adopted without testing the project’s noisy separated inputs.
8. **Primary evaluation guidance — continuous wake false accepts:** [openWakeWord repository’s Performance and Evaluation section](https://github.com/dscripka/openWakeWord#performance-and-evaluation). It recommends realistic wake positives and hours of representative continuous negative audio, and notes sample-size caveats. This is an implementation project’s evaluation protocol, not peer-reviewed evidence, but it directly illustrates why a few seconds cannot estimate false actions/hour.
9. **Primary dataset paper — FSC:** Lugosch et al., [“Speech Model Pre-Training for End-to-End Spoken Language Understanding,” Interspeech 2019](https://www.isca-archive.org/interspeech_2019/lugosch19_interspeech.html). Introduces Fluent Speech Commands as single recordings of commands and includes speaker-disjoint partitioning. It matches the intent inventory, not the continuous wake-triggered input condition.
10. **Primary dataset paper — Speech Commands:** Warden, [“Speech Commands: A Dataset for Limited-Vocabulary Speech Recognition,” arXiv 2018](https://arxiv.org/abs/1804.03209). It is an isolated-word KWS benchmark with standardized split conventions; it is useful for source wake clips, but not full utterance-level wake-to-intent evaluation.
11. **Primary corpus repository — Hey Snips:** Sonos, [keyword-spotting-research-datasets](https://github.com/sonos/keyword-spotting-research-datasets). Its README verifies “Hey Snips” examples, speaker metadata, same-domain negatives, split descriptions, access by request, and research-only restrictions. It is not a ready-made intent corpus.
12. **Public dataset record — Smart Speaker Command Dataset:** DiPassio et al., [University of Rochester Figshare dataset record](https://doi.org/10.60593/ur.d.26417548), with [manual](https://rochester.figshare.com/ndownloader/files/48058369). The record states that commands begin “Hey Alexa,” archive size 448.68 MB, and CC BY 4.0. The trigger and unverified manifest details make it a lead for later schema inspection, not a compatible “Marvin” acceptance set.
13. **Statistical methods — rare-event exposure:** NIST, [Technical Note 2118, False Alarm Testing for Radiation Detection Systems](https://doi.org/10.6028/NIST.TN.2118). Although from another detection domain, it lays out false alarms per unit exposure and Poisson count-based acceptance/uncertainty. The `2.996/T` zero-count one-sided 95% bound follows by solving `P(N=0)=exp(-λT)=0.05`; its use here assumes a constant Poisson rate and should be supplemented by condition/session breakdowns.
14. **Conference paper — selective classification:** Geifman and El-Yaniv, [“Selective Classification for Deep Neural Networks,” NeurIPS 2017](https://papers.neurips.cc/paper_files/paper/2017/file/4a8423d5e91fda00bb7e46540e2b0cf1-Paper.pdf). It studies rejection rules that target a desired risk while retaining coverage, using image-classification experiments. This supplies general evaluation vocabulary and does not validate abstention behavior for audio or the current intent model.

## Recommended sequence


Use three disjoint data partitions for any follow-up training and evaluation: (a) training sessions may supply training examples and hard-negative mining; (b) development sessions may calibrate confidence and select model settings, thresholds, and event policy, but must never contribute training/mining examples; and (c) locked test sessions are used once after all choices are frozen. First add or use an evaluation-only recorder around the existing runtime and run a matched same-speaker diagnostic. Do not change SpEx, default weights, or broad thresholds while this evidence is being collected. Next repair only the stage shown to lose the command or make the error. For Stage 3, mine actual hard negatives from the training partition and tune joint temporal behavior on development sessions. For Stage 4, use aligned frozen-SpEx examples, assess calibration, and add a defer behavior if development risk-coverage evidence supports it. Then freeze code, weights, thresholds, calibration, and event-counting rules and run one locked test on held-out speakers/sessions with enough target-absent hours for the stated false-action bound. Report end-to-end correct actions, misses, false actions per target-absent hour with uncertainty, conditional intent accuracy, and median/p95 latency. Component metrics remain diagnostic and cannot establish production readiness by themselves.
