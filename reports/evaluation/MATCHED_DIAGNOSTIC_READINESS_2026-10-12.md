**Snapshot:** 12 October 2026  
**Purpose:** Decide whether the recommended instrumented wake-to-intent replay can be run honestly with the audio currently available, and define the minimum recording and trace needed to make it actionable.

## Readiness decision

The requested same-person continuous replay is **not ready to run**. The configured E: data volume contains Speech Commands v2, Fluent Speech Commands, and CAVEMOVE, but the custom in-car recording folders are empty. The two speech corpora do not share verified speaker identities. No recording was run or represented as matched evidence, and no audio was generated by joining clips.

The top-level E: directory and the relevant `E:\car-tse-data` directories were inspected by name, then the configured custom recording folders and known corpus roots were checked directly. This was a targeted inventory, not a recursive scan of all E: files. No eligible same-person continuous recording was found in those inspected roots.

The repository audit remains the correct interpretation of v10: it establishes which source-time spans were appended in the synthetic cross-corpus scenes; it does not establish that SpEx preserved the target command. In four timely scenes the classifier was wrong despite source-time overlap, and in four late scenes the appended interval contained no target command. Neither group identifies a same-driver root cause.

## What the current evaluator captures—and what is missing

The existing evaluator is a useful starting point. Its scene loop advances in explicit sample-indexed windows and passes `audio_start_sample` to the runtime (lines 623–642). Its observer tracks accepted command-buffer source segments across skipped intervals (lines 550–620), then records timeline overlap in `describe_intent_capture` (lines 462–525). Keep that exact-segment method; the v9 estimate must not return.

The existing cross-corpus evaluator still does **not** save the actual fixed-length waveform received by the Stage 4 model. `describe_intent_capture` reports segment times and sample counts, while the runtime builds the tensor in `_prepare_intent_input` and passes it to `self.intent` (`src/car_tse/pipeline/in_car_pipeline.py`, lines 317–351). A new separate utility now closes that capture gap: `scripts/eval/replay_matched_continuous_diagnostic.py` uses an intent forward pre-hook to save the exact post-padding/post-truncation tensor as a dtype-preserving `.pt` file and records its shape and content hash. It also saves each call's raw and normalized Stage 1 tensors, Stage 2 logits and overall/tail/fresh probabilities, every call's gate/wake fields, and each actual command-buffer append. Appended tensors keep a null source span when mapping is incomplete, including final padded windows.

The per-window JSON currently logs the public overall `presence_probability`, acceptance, wake score, command state, and output fields (evaluator lines 670–697). For framewise presence, the runtime separately computes overall, post-KWS-tail, and newly-arrived-region probabilities in `_presence_statistics` (runtime lines 364–395), but returns only the overall value through `PipelineOutput`. A replay observer should wrap this helper or capture its returned tuple to log all three values for every call. It should also record the pre/post command-buffer length, `awaiting_command`, speaker-similarity score, and the rejection reason (`overall_below_threshold`, `fresh_region_below_threshold`, `speaker_gate`, or accepted). The exact reason must be computed from the active threshold and runtime branch for that call, not inferred later from timeline overlap.

`PipelineOutput.s1` exposes the Stage 1 waveform used for downstream processing. The new observer saves raw `s1` and the separately normalized waveform produced by `normalize_extracted_waveform` (`src/car_tse/pipeline/in_car_pipeline.py`, lines 56–67), plus the source multichannel WAV and the exact arithmetic-mean mono input. It records channel metadata when supplied, sample rate, sample intervals, and content hashes. Do not call normalized audio “raw extraction.”

## Minimal recording and trace contract

Record one uninterrupted, timestamped microphone stream from the enrolled person in one session. The same person must provide an independent enrollment clip, then say the configured wake phrase and one labeled command in the stream. Mark wake onset/offset, command onset/offset, transcript, and expected intent against the original stream. Record a small set of trials across quiet and representative cabin noise; include different natural pauses between wake and command. A second person or playback can be included in a later diagnostic condition, but the initial positive must be clearly attributable to the enrolled speaker. Use a stable pseudonymous speaker/session key and retain the consent and recording-device/channel metadata.

Each replay should write a machine-readable manifest and an event trace. The utility requires a JSONL trial row with, at minimum, the fields below. The IDs and evidence fields make the human provenance auditable; the validator checks they agree but cannot itself identify a person's voice or prove that the assertion is true.

| Record | Required values |
|---|---|
| Trial metadata | `trial_id`, pseudonymous `speaker_id`, `session_id`, `sample_rate_hz`, channel names/order, expected intent, independent enrollment path, source-audio path. |
| Speaker provenance | `speaker_match_verified: true`, reviewer and evidence text, plus equal `speaker_id`, `stream_speaker_id`, `wake_speaker_id`, `command_speaker_id`, and `enrollment_speaker_id`. A reviewer must establish this from the recording/session or trusted provenance; IDs alone are insufficient. |
| Ground truth | `wake_start_sample`, `wake_end_sample`, `command_start_sample`, `command_end_sample` as integer sample counts; `event_annotation_method` and `annotation_reviewer`; `command_transcript` and `command_transcript_reviewed: true` after listening to the source. The validator checks ordering and file bounds. |
| Per-call input | Call index, stream window start/end samples, fresh/new source interval, mono and multichannel shape, and whether the call overlaps a prior timestamped window. |
| Stage 1 | Raw extracted tensor and normalized downstream tensor for the exact call; shape, peak/RMS, source interval, and file/checksum. |
| Stage 2 | Raw frame logits or per-frame probabilities when framewise; overall, post-KWS-tail, and fresh-region probabilities; active threshold; accepted/rejected decision and explicit reason. Include rejected/skipped calls. |
| Stage 3 | Wake probability on every call where KWS ran, active cutoff, smoothing support/hit count, refractory state before and after the call, and wake event time. Record `not_evaluated` distinctly from a low score after Stage 2 rejection. |
| Capture | `awaiting_command` before/after the call; command-buffer sample count before/after; exact appended tensor and its source sample interval(s); any gate-skipped interval; wake-time pre-roll interval. |
| Stage 4 | Exact tensor copied by an intent-module forward pre-hook after fixed-length padding/truncation, tensor sample rate and length, checksum, prediction logits/probabilities, selected intent/action, and decision time. |

The comparison should be audible and sample-aligned: source command crop, raw Stage 1 output over the matching call, normalized Stage 1 output, concatenated accepted command samples, and the exact Stage 4 tensor. This can show whether words disappear at extraction, are skipped by the gate, are truncated/padded at capture, or remain present but are misclassified. If time alignment becomes ambiguous because extraction changes duration, report the ambiguity and listen to both signals; source-time overlap alone is not proof of word survival.

## Implemented observer and use after recordings arrive

The standalone utility is present at `scripts/eval/replay_matched_continuous_diagnostic.py`. It accepts one multichannel source stream, a separate enrollment clip, and the declared manifest fields above. It constructs the same model pipeline through the existing proxy loader, uses an instrumented subclass rather than permanent monkey-patching, saves trace/audio/tensors locally, and records hashes for the manifest, configs, checkpoints, source, enrollment, observer code, and available Git state. It rejects mismatched sample rates, out-of-range events, duplicate enrollment content, and incomplete or inconsistent speaker metadata before inference. It refuses to overwrite a non-empty output directory.

When a qualifying recording is available, run one replay with the locked current checkpoints and config in `audioml_base`, explicitly enable W&B, and write all artifacts locally:

```powershell
conda run -n audioml_base python scripts/eval/replay_matched_continuous_diagnostic.py `
  --manifest E:/car-tse-data/custom_incar/manifests/matched_continuous.jsonl `
  --config configs/eval_continuous_pipeline_p0_e.yaml `
  --paths configs/paths.e_research.yaml `
  --output-dir reports/evaluation/artifacts/matched_continuous `
  --wandb
```

The command is a future invocation, not a run completed in this audit. There is no eligible manifest or audio today. The synthetic test fixture only verifies the observer: it confirms parity of pipeline outputs, intent logits, action and state with instrumentation active; exact equality between the saved Stage 4 tensor and the baseline pipeline's intent pre-hook tensor; and cleanup of both hooks after normal exit and exception. It also checks that padded tail audio is saved but receives no invented source interval. In `audioml_base`, `py_compile` passed and `pytest -q tests/test_matched_continuous_diagnostic.py` passed **4 tests**. These tests make no performance claim.

Do not tune thresholds or train during the eventual replay. The next decision should follow the first point where known command content is lost or the first incorrect decision; only then propose a stage-specific code or model change. Do not infer production readiness from the one diagnostic.
