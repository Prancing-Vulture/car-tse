# SLURP apples-to-apples comparison status

Date: 2026-10-18  
Status: dataset acquisition and protocol preparation in progress

## Scope

This work establishes a common English spoken-language-understanding benchmark
for comparison with Paranjape et al. and Hussein et al. It does not treat their
headline numbers as directly comparable: Paranjape et al. evaluate a RASA text
assistant on 300 intent examples, while Hussein et al. report a small command
classification experiment. Neither paper evaluates target-speaker extraction,
passenger rejection, continuous wake-to-action authorization, or the current
four-stage in-car pipeline.

The common benchmark is SLURP intent recognition. A separate synthetic/recorded
scene benchmark is required for the full wake-to-action comparison because
SLURP contains isolated single-turn assistant utterances, not enrollment,
wake-word, passenger, and vehicle-noise sessions.

## Annotation audit

The local audit is implemented by
`scripts/data/audit_slurp.py`. It preserves the official JSONL entries and
creates optional flat recording manifests under `D:\datasets\slurp\manifests`.

| Official split | Annotation rows | Real recordings | Close-talk | Distant | Intents | Actions | Scenarios |
|---|---:|---:|---:|---:|---:|---:|---:|
| train | 11,514 | 50,628 | 24,210 | 26,418 | 91 | 46 | 18 |
| devel | 2,033 | 8,690 | 4,173 | 4,517 | 71 | 45 | 18 |
| test | 2,974 | 13,078 | 6,281 | 6,797 | 77 | 46 | 18 |
| train_synthetic | 19,711 | 69,253 | 0 | 69,253 | 98 | 54 | 18 |

The counts agree with the SLURP paper for the real train/development/test
partitions. The released metadata identifies 177 speakers overall, but the
official split files are not speaker-disjoint: the same speaker IDs occur in
multiple official partitions. Consequently, the results will be labelled as:

1. **Official SLURP protocol:** exact released train/devel/test split, with
   close-talk and distant recordings evaluated separately. This is the correct
   comparison to published SLURP results, but not an unseen-speaker test.
2. **Speaker-disjoint stress protocol:** a deterministic derived split that
   assigns each complete speaker ID to exactly one partition. This supports an
   unseen-driver/generalization claim and will be reported separately.

The reproducible derived split is generated by
`scripts/data/build_slurp_speaker_disjoint.py` with seed `20261018`. It keeps
174 metadata-labelled speakers together and produces 58,437/6,953/7,000
recordings for train/devel/test. Six real recordings lack a metadata speaker
ID and are excluded from this stress protocol; they remain part of the
official-protocol manifests.

## Planned measurements

### Track A — paper task reproduction

For each paper, record the actual dataset, class inventory, split, acoustic
input, and meaning of “accuracy.” If a paper's private/custom data cannot be
recovered, mark the reproduction as unavailable rather than substituting SLURP.

### Track B — common clean SLURP intent benchmark

Using the frozen local code and fixed seeds, report:

- direct audio-to-intent accuracy, macro-F1, and top-5 accuracy;
- scenario accuracy and action accuracy;
- exact semantic-frame accuracy and entity/slot F1 where the model supports it;
- close-talk and distant-microphone results separately;
- official and speaker-disjoint protocols separately;
- latency on the same host and with the same input duration.

The first model will be a documented wav2vec2-base frozen-feature + 91-class
head baseline. It is a clean intent baseline only; it will not be presented as
a replacement for the target-speaker pipeline.

### Track C — full in-car pipeline

SLURP cannot by itself validate this track. We will use a separate fixed scene
set containing same-speaker enrollment, wake word, command, passenger speech,
no-command negatives, and controlled overlap. The current TSE, presence gate,
speaker authorization, wake smoothing, and intent model will be compared with
one-component-disabled ablations on exactly the same scenes.

## Reproducibility rules

- Never train on official test recordings.
- Keep all audio under `D:\datasets`, outside git.
- Verify and record archive MD5 before extraction.
- Do not call the official SLURP split speaker-independent.
- Report exposure time for false wakes/actions; do not infer safety from intent
  accuracy alone.
- Keep the current TSE checkpoint frozen for the first apples-to-apples run;
  any SLURP intent head is a separately named candidate.
