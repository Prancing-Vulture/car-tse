# SLURP apples-to-apples comparison status

Date: 2026-10-18  
Status: dataset acquired, checksummed, extracted, and comparison tooling ready

## Scope

This work establishes a common English spoken-language-understanding benchmark
for comparison with Paranjape et al. and Hussein et al. It does not treat their
headline numbers as directly comparable: Paranjape et al. evaluate a RASA text
assistant on 300 intent examples, while Hussein et al. report a small command
classification experiment. Neither paper evaluates target-speaker extraction,
passenger rejection, continuous wake-to-action authorization, or the current
four-stage in-car pipeline.

The common benchmark is SLURP intent recognition. A separate synthetic/recorded
scene benchmark is required for the full wake-to-action comparison because
SLURP contains isolated single-turn assistant utterances, not enrollment,
wake-word, passenger, and vehicle-noise sessions.

## Annotation audit

The local audit is implemented by
`scripts/data/audit_slurp.py`. It preserves the official JSONL entries and
creates optional flat recording manifests under `D:\datasets\slurp\manifests`.

| Official split | Annotation rows | Real recordings | Close-talk | Distant | Intents | Actions | Scenarios |
|---|---:|---:|---:|---:|---:|---:|---:|
| train | 11,514 | 50,628 | 24,210 | 26,418 | 91 | 46 | 18 |
| devel | 2,033 | 8,690 | 4,173 | 4,517 | 71 | 45 | 18 |
| test | 2,974 | 13,078 | 6,281 | 6,797 | 77 | 46 | 18 |
| train_synthetic | 19,711 | 69,253 | 0 | 69,253 | 98 | 54 | 18 |

The post-extraction audit found all 50,628/8,690/13,078 real recording
references and all 69,253 synthetic recording references. The archives contain
72,395 unique real FLAC files and 69,257 synthetic FLAC files; the real
manifests contain 72,396 references because one filename is reused, while the
four extra synthetic files are not referenced by the released JSONL entries.

The counts agree with the SLURP paper for the real train/development/test
partitions. The paper's summary table lists 177 speakers; the local metadata
attached to the published real recordings identifies 174 speaker IDs. The
official split files are not speaker-disjoint: the same speaker IDs occur in
multiple official partitions. Consequently, the results will be labelled as:

The raw `intent` strings also contain cross-split naming variants (for example
`music_likeness` versus `likeness`, and `recommendation_locations` versus
`locations`). The primary audio baseline therefore predicts the stable
46-class `action` field, which is the semantic level used for the published
SLURP action results. Raw intent-string results will not be reported as if
they were a single clean class inventory.

1. **Official SLURP protocol:** exact released train/devel/test split, with
   close-talk and distant recordings evaluated separately. This is the correct
   comparison to published SLURP results, but not an unseen-speaker test.
2. **Speaker-disjoint stress protocol:** a deterministic derived split that
   assigns each complete speaker ID to exactly one partition. This supports an
   unseen-driver/generalization claim and will be reported separately.

The reproducible derived split is generated by
`scripts/data/build_slurp_speaker_disjoint.py` with seed `20261018`. It keeps
all 174 local speaker IDs together and produces 58,441/6,953/7,002 recordings
for train/devel/test. All real recording references have speaker metadata and
are retained in this stress protocol.

## Planned measurements

### Track A — paper task reproduction

For each paper, record the actual dataset, class inventory, split, acoustic
input, and meaning of “accuracy.” If a paper's private/custom data cannot be
recovered, mark the reproduction as unavailable rather than substituting SLURP.

### Track B — common clean SLURP intent benchmark

Using the frozen local code and fixed seeds, report:

- direct audio-to-intent accuracy, macro-F1, and top-5 accuracy;
- scenario accuracy and action accuracy;
- exact semantic-frame accuracy and entity/slot F1 where the model supports it;
- close-talk and distant-microphone results separately;
- official and speaker-disjoint protocols separately;
- latency on the same host and with the same input duration.

The first model will be a documented wav2vec2-base frozen-feature + 46-class
action head baseline. It is a clean SLURP action baseline only; it will not be
presented as a replacement for the target-speaker pipeline.

### Initial official action baseline

The first run completed with the pretrained `facebook/wav2vec2-base-960h`
encoder frozen, mean-pooled features from a fixed 4.0-second waveform, a
512-unit MLP head, class-balanced sampling, and 16 head-training epochs. The
best development macro-F1 was 17.75% at epoch 15. Held-out test results were:

| Test view | Accuracy | Top-5 | Macro-F1 | Recordings |
|---|---:|---:|---:|---:|
| all real microphones | 19.32% | 50.91% | 18.10% | 13,078 |
| distant only | 14.59% | 43.20% | 13.56% | 6,797 |
| close-talk only | 24.44% | 59.26% | 23.26% | 6,281 |

This is a deliberately simple lower-bound baseline, not the final comparison
model. The distant/close-talk gap is useful evidence that acoustic capture
matters. It also explains why the published 93% figures cannot be compared as
if they were the same task: those figures are text or small command-classifier
results, while this run is direct audio-to-action classification over 46
SLURP actions. The raw epoch log and paper-ready plot are kept at
`D:\datasets\slurp\artifacts\logs\slurp_action_wav2vec_official_all_2026-10-18`
and `reports/figures/slurp_action_wav2vec_official_all_2026-10-18.{png,pdf}`.

The next comparison model should fine-tune a streaming-capable acoustic
encoder or use an ASR-to-NLU baseline, then report both official and
speaker-disjoint scores. The current run is retained as the frozen-feature
reference so improvements remain measurable.

### Initial speaker-disjoint stress baseline

The identical frozen-feature/action-head configuration was retrained on the
deterministic 80/10/10 speaker-disjoint split. Its best development
macro-F1 was 22.89% at epoch 15. The derived held-out test results were:

| Test view | Accuracy | Top-5 | Macro-F1 | Recordings |
|---|---:|---:|---:|---:|
| all real microphones | 23.28% | 54.93% | 22.85% | 7,002 |
| distant only | 17.01% | 46.49% | 16.17% | 3,734 |
| close-talk only | 30.45% | 64.57% | 31.07% | 3,268 |

The stress result is not directly comparable to the official SLURP test because
it uses a different speaker assignment and has a different train/test mixture.
It is included to expose speaker-generalization behavior and to prevent the
official split's speaker overlap from being mistaken for an unseen-driver
result. Its training log and plot are at
`D:\datasets\slurp\artifacts\logs\slurp_action_wav2vec_speaker_disjoint_2026-10-18`
and `reports/figures/slurp_action_wav2vec_speaker_disjoint_2026-10-18.{png,pdf}`.

### Track C — full in-car pipeline

SLURP cannot by itself validate this track. We will use a separate fixed scene
set containing same-speaker enrollment, wake word, command, passenger speech,
no-command negatives, and controlled overlap. The current TSE, presence gate,
speaker authorization, wake smoothing, and intent model will be compared with
one-component-disabled ablations on exactly the same scenes.

## Reproducibility rules

- Never train on official test recordings.
- Keep all audio under `D:\datasets`, outside git.
- Verify and record archive MD5 before extraction.
- Do not call the official SLURP split speaker-independent.
- Report exposure time for false wakes/actions; do not infer safety from intent
  accuracy alone.
- Keep the current TSE checkpoint frozen for the first apples-to-apples run;
  any SLURP intent head is a separately named candidate.
